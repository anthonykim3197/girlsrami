# 관리자 상품 구분과 입고일

입고일은 점주가 상품 자료를 처음 전달하고 작업을 요청한 날짜다. 한국 시간(Asia/Seoul) 기준이며 실물 창고 입고일, 상품 게시일, 사진 수정일과 구분한다. 공개 상품의 `releasedAt`을 입고일로 재사용하지 않는다.

| 구분 | 입고일 | 상품 수 | 품번 |
|---|---|---:|---|
| 신규 디자인 | 2026-10-13 | 9 | JO23, JO24, JO31, JO32, RM542, RM543, RM567, RM576, RM582 |
| 초기 신규 디자인 | 2026-10-03 | 2 | RM382, RM495 |
| 기존 스마트스토어 판매 상품 | 미확인 | 10 | RM274, RM277, RM279, RM336, RM375, RM385, RM401, RM418, RM429, RM471 |

최초 작업 요청 기록을 기준으로 최근 날짜부터 정렬하고, 확인되지 않은 날짜는 마지막에 둔다. 기존 10종의 후속 상세페이지 개선 요청일을 최초 입고일로 추정하지 않는다. 판매량·주문 수는 연결되지 않았으므로 재고나 리뷰 수를 판매량으로 표시하지 않는다.

## 근거

- 신규 9종: 2026-10-13 14:12:17 KST, 사용자가 `new_goods` 폴더와 그레이카드가 포함된 새 촬영 자료를 전달한 메시지. 원본 UTC `2026-10-13T05:12:17.116Z`.
- 초기 2종: 2026-10-03 01:08:34 KST, 사용자가 `new_goods`의 점주 촬영 사진 검토를 요청한 메시지. 원본 UTC `2026-10-02T16:08:34.864Z`. 같은 작업의 검토 결과에서 RM382와 RM495를 명시했다.
- 로컬 메시지 위치는 별도 작업 감사 기록에 보존하며, 사용자 대화 전문은 배포 저장소에 포함하지 않는다.
- 기존 10종의 최초 자료 전달일은 현재 기록에서 확인하지 못했다.

## 저장과 표시

- `catalogGroup`: `new`(신규 디자인), `legacy`(기존 스마트스토어), `sample`(견본), `test`(테스트), `unclassified`(미분류).
- `intakeDate`: `YYYY-MM-DD` 또는 `null`. 관리자 편집에서 수정할 수 있다.
- 확인된 40개 상품의 최초 구분과 날짜는 `admin-catalog.js`에 보존한다. 초안에 명시적으로 저장한 구분·날짜가 우선한다. 빈 날짜를 저장하면 자동으로 과거 날짜를 채우지 않는다.
- 실제 상품의 판매 상태와 판매 중 개수는 게시본을 기준으로 표시한다. 초안을 편집했다는 이유로 공개 판매 수가 바뀌지 않는다.
- 견본 8개와 테스트 11개는 기본 실제 상품 표에서 제외하고 별도 탭에서 조회한다. 삭제하거나 판매 상태를 바꾸지 않는다.
- 새로운 ID는 이름·이미지·구매 주소만 보고 견본으로 추정하지 않으며 미분류에 둔다.
- 과거 게시 내용을 초안으로 복원해도 현재 입고일과 구분은 보존한다.

검증: `npm run test:admin`, `npm run build` 및 로그인한 관리자 화면에서 목록·검색·묶음별 개수·편집·모바일 표를 확인한다.
