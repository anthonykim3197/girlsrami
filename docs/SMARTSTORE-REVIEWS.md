# 스마트스토어 구매후기 운영

자사몰은 스마트스토어에서 확인한 구매후기를 **수동 스냅샷**으로 보여 준다. 현재 RM401(`stripe-cable-half`, 네이버 상품번호 `8424655623`)만 수록한다. 실시간 연동이나 자사몰 자체 후기 접수 기능은 아니다.

## 파일과 근거

- `smartstore-reviews.js`: 공개용 후기 발췌, 원문 링크, 확인일, 별점·총 건수, 후기 ID·날짜·종류·옵션, 마스킹된 작성자, 사진 경로.
- `product.html`: 위 데이터 파일을 상세페이지 렌더러보다 먼저 읽는다.
- `standard-detail.js`: `GR_SMARTSTORE_REVIEWS[상품ID]`를 표시한다. 기존 `p.reviews`와 합치지 않는다.
- `assets/detail/stripe-cable-half/reviews/`: 확인한 후기 사진 3장.
- 별도 작업자료 `reviews-20261015/source-record.json`, `image-receipts.json`: 2026-10-15 원문 확인 기록과 사진 수집 근거. 후기 원문 전문·자격증명·비공개 고객정보를 이 문서에 복제하지 않는다.

[RM401 스마트스토어 원문](https://smartstore.naver.com/girlsrami/products/8424655623#REVIEW_DIALOG)에서 2026-10-15 확인한 총 4건, 평점 4.75를 사용한다. 화면의 확인일을 함께 표시하고 갱신된 값처럼 소개하지 않는다.

## 이전 데이터 조사 결과

- 현행 `data.js`의 판매상품 12개는 모두 `reviews: []`다. RM401의 평점 4.75·4건은 2026-10-06 상품 수집자료의 `simpleProductForDetailPage.reviewAmount`와 일치한다. 그 파일에는 후기 본문이 없다.
- `member.js`의 카탈로그 변환은 `reviews: [], rating: 0, reviewCount: 0`으로 덮는다. 별도 스냅샷을 사용하는 이유다. 상품 DB에 후기 배열만 추가해서는 현행 표시 경로가 해결되지 않는다.
- 예전 시연용 `site-remodel/data.js`에는 다른 상품 3개의 후기 문구 6건이 하드코딩되어 있다. 원문 후기 ID·URL·확인일이 없어 진위를 검증하지 못했으므로 가져오지 않는다. RM401 본문은 이곳에도 없었다.
- `site-remodel/scripts/seed-sql.mjs:8`도 후기·평점을 빈 배열과 0으로 초기화한다. 확인한 마이그레이션·관리자 양식에는 구매후기 전용 테이블·입력 기능이 없고, 후기 수집·내보내기·가져오기 도구나 네이버 커머스 API 연동도 찾지 못했다. `content-review`는 룩북 게시 전 검수용 저장소이며 구매후기 DB가 아니다.
- 위 판단은 확인한 저장소와 로컬 자료 범위다. 운영 DB의 모든 내부 테이블 부재를 조사한 것은 아니다.

## 갱신 절차

1. 해당 스마트스토어 상품의 구매후기 화면에서 총 건수·평점·후기 목록과 원문 변경 여부를 확인한다. 여러 페이지라면 전체 범위를 확인한다.
2. `source + productId + review.id`를 고유키로 사용한다. 같은 ID는 덧붙이지 말고 수정한다. 작성자가 같아도 일반 후기와 한달사용 후기의 ID가 다르면 별도 후기다.
3. 상품별 최신 확인 목록으로 전체 기록을 교체하는 방식을 우선한다. 일부 페이지만 확인했다면 누락을 삭제로 간주하지 않는다. 원문 삭제·비공개가 확인된 후기는 발췌와 사진 연결도 함께 제거한다.
4. 원문 링크·후기 ID·작성일·옵션·종류를 보존한다. 작성자 표시는 네이버의 마스킹 수준을 유지하거나 더 가린다. 실명·연락처·주문번호 등 추가 개인정보를 저장하지 않는다.
5. 문구는 원문 그대로 짧게 인용하고 일부만 쓸 경우 `excerpt: true`로 표시한다. 맞춤법이나 표현을 임의로 미화하지 않고, 구매자가 적은 아쉬운 점을 지워 추천문처럼 바꾸지 않는다.
6. 현재 4점 후기와 한달사용 후기를 유지한다. 좋은 평점만 골라 전체 후기인 것처럼 표시하지 않는다. 네이버가 제공한 전체 평점·총 건수를 자사몰 발췌 목록의 평균·건수와 섞지 않는다.
7. 사진 추가·교체는 원문 후기와 연결된 파일만 사용하고 수집 근거를 남긴다. 삭제된 원문 사진은 노출을 중단한다. 사진 링크·모바일 표시·확대 동작을 확인한다.
8. `checkedAt`을 실제 확인일로 갱신한다. 중복 ID, 없는 이미지, 잘못된 상품 연결을 검사한 뒤 통상적인 사이트 빌드·검수·배포 절차를 거친다. 이 갱신에는 상품 가격·재고나 상품 DB 수정이 필요하지 않다.

## 새 후기 작성 안내

구매자는 **네이버페이(Npay) → 결제 내역 → 해당 주문 → 구매확정 후 리뷰 쓰기**에서 작성한다. 이미 구매확정된 주문은 결제 내역의 리뷰 쓰기를 안내한다. 로그인 계정과 주문 상태에 따라 버튼 표시가 다를 수 있다.

자사몰의 후기 확인·작성 링크는 네이버 구매후기 또는 Npay로 안내한다. 자사몰에서 접수 완료나 자동 반영을 약속하지 않는다. 새 후기와 수정·삭제 사항은 운영자가 다음 스냅샷을 확인하고 배포한 뒤 자사몰에 반영된다.
