# 화면 전환과 RM401 코디 보완 검증

## 원인과 변경

- 운영 상품 진입 관찰: 373ms에 구형 `.pd`, 935ms에 `.grsd`로 교체되며 주 이미지 src가 일시적으로 없어졌고, 966ms에 복구됐다. 상품 높이도 약 1,144px에서 7,979px로 바뀌었다.
- 공통 메뉴가 원격 catalog boot를 기다렸고, 목록의 정적/동적 구조와 순서가 달랐다. 교체된 카드에 숨김→등장 효과가 다시 적용됐다. 전역 smooth scroll도 제거했다.
- 빌드와 브라우저에 동일한 마크업을 공유했다. 검증된 후기 요약을 정렬·카드에 공통 사용하고, 홈 NEW 순서를 고정했다. 장바구니 준비 상태는 상세 전체를 교체하지 않고 갱신한다.

## 확인한 동작

환경: macOS의 Ego Chromium, 데스크톱 1440/1512px 및 모바일 에뮬레이션 390×844. 실제 사용자의 Whale 프로필에서는 직접 실행하지 않았다.

- 수정 전 오른쪽 50px 드래그: 0°→45°. 수정 후 오른쪽: 0°→315°, 왼쪽: 315°→0°.
- 운영 catalog를 읽는 로컬 배포본에서 판매 12종의 초기 상세 구조 확인. 메인 이미지 노드 재사용을 확인하고, 장바구니 상태 차이 때문에 교체되던 RM382/RM495도 수정 후 재사용 확인.
- 홈·목록·브랜드·구매 안내에서 동일한 메뉴 유지. 홈·목록 카드 노드 재사용 확인.
- 목록 y=963.5에서 상품 진입→뒤로가기 후 y=963.5 복원. 니트/낮은가격 필터도 URL과 선택 상태 그대로 복원.
- RM401 4코디×5색 20조합의 선택 이미지 로딩 확인. 모바일 초록/데님, 제품 단독 회전 모드 확인. 360은 대표 코디 세트.
- catalog 요청 차단 시 제목·주 이미지·실측을 유지하고 장바구니만 비활성화하며, 정확한 SmartStore 상품 구매 링크 유지.
- 자동 검사 84개 통과. `npm run build`, `npm run test:storefront`, `git diff --check` 사용. 판매 종료 시 SSR 하단 잔존 회귀도 수정하고 검사에 포함했다.

- 데이터베이스 변경 없음. 이전 배포 커밋은 `0162aa567c04a83d358cfc516b18c1fa7b94e8d6`.
- 브랜치 preview 빌드 성공 확인 후 운영에 반영한다. 상품 표시/선택/구매 연결이 깨지면 이전 배포로 복구한다.
